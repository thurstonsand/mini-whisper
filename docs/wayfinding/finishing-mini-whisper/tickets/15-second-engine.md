# Second engine / fallback hardening (stake 5)

## Question

Reworded from 'Parakeet second engine' after the bakeoff inverted the stack: FluidAudio/Parakeet is primary, whisper.cpp Medium.en is the recorded contingency. Decide what hardening the fallback path needs — a shippable second engine behind ASREngine, a maintained branch, or retirement — driven by FluidAudio's observed reliability in daily use.

## Notes

- **The corpus is gone.** The [Cohere run](26-cohere-transcription-model.md) found that the engine bakeoff's 24 private recordings no longer exist — only `assets/09-engine-bakeoff/fixtures/local-manifest.json`'s reference text survives, which is useless without its audio. Every engine decision this project has made rests on measurements that can no longer be reproduced or extended, so any candidate weighed here starts from nothing.
- Rebuilding it by hand is what happened last time. [History](11-history.md) makes it a byproduct instead: transcripts paired with their audio, accumulated by ordinary use, with hand-corrected entries worth more than clean ones. That was filed as an incidental benefit of history; the corpus loss promotes it to the reason this ticket can be answered at all.
- The corrected-transcript question therefore belongs to history's design, not this one — raise it there before this ticket opens.
- **Re-examine v2 over v3 first, before any second engine.** The [bakeoff](09-engine-bakeoff.md) picked Parakeet v2 on a margin of *one word* across 24 private recordings — 3.21% against v3's 3.29% — plus a seam-duplication artifact in v3's default path. One word is noise, the corpus that produced it no longer exists, and the [Cohere addendum](../assets/26-cohere-transcription-model/README.md) finds public data pointing the other way: Artificial Analysis measures v3 at 4.5% against v2's 6.4% on dictation-like audio. Both artifacts are already pinned and both load in the same FluidAudio runtime, so this is the cheapest accuracy experiment available — and the one that has to run before spending anything on a second engine.
- **Moonshine is a candidate to weigh alongside whisper.cpp.** Whispering — the app the allowlist already sanctions — offers it next to Parakeet and Whisper, which is the cheapest available signal that it is viable for dictation. [Useful Sensors' Moonshine](https://huggingface.co/UsefulSensors/moonshine) is MIT, English-only, and sized for edge devices; it drops Whisper's fixed 30-second padding for variable-length processing, so cost scales with utterance length — the exact shape of this app's workload. Its published WER claims a slight edge on same-size Whisper models. The open question is runtime: weights ship as ONNX/Keras with no FluidAudio or Core ML path, so a Swift integration means onnxruntime or a conversion of our own, and a new inference runtime is an allowlist question before it is an accuracy one. Answer that before spending anything on measurement.
- [Cohere](26-cohere-transcription-model.md) is the standing revisit-later candidate: excluded on today's Core ML conversion at 532 ms p50 and ~12 GB RSS, worth re-measuring if a faster or leaner Apple artifact appears.
- **The revisit trigger fired (2026-08-19).** Superwhisper's [S1 announcement](https://superwhisper.com/blog/s1) names "Cohere Transcribe (local)" as its recommended *offline default* on consumer Macs — a shipping consumer-grade local deployment exists, so the exclusion's premise (no lean Apple artifact) deserves re-measurement. How they run it — their own conversion, MLX, quantization — is the first question of the revisit.
- **The corpus objection is retired.** The [dictation corpus](../assets/43-dictation-corpus/) gives this ticket what the bakeoff lost: stage 1 (Harvard list + confusables) is recorded per mic/noise condition with committed reference text, so engine candidates — Parakeet v2 vs v3, Cohere Transcribe, Moonshine, and the Whisper family itself (whisper.cpp large-v3 / turbo / Medium.en, the recorded contingency, which has never actually been measured against our own voice) — now measure against a reproducible, extendable fixture instead of nothing.
- **The contingency is measured (corpus round 2, [results](../assets/43-dictation-corpus/results/)):** whisper.cpp medium.en and large-v3-turbo both land at 3.90% stage-1 WER vs Parakeet's 1.95%, at 422–487 ms vs 55 ms — warm times, spawn excluded. Parakeet also wins every e2e cleanup row. The fallback is real but strictly worse on every axis; whisper also pre-resolves symbols and deletes disfluencies, so it feeds the cleanup a different task. Cohere Transcribe remains unmeasured behind a HF contact gate; `mlx-audio` ≥ 0.4.2 is the identified runtime, mooting asset 26's Core ML numbers.
- **The corpus caught a documented Parakeet weakness:** polish-11's "quote/unquote" and polish-38's letter-by-letter spelling vanish from Parakeet transcripts while both whisper models hear them fine. Known family traits: the 0.6b-v2 card's discussions report disfluency/repeated-word blindness (a regression from 1.1b), and TDT decoding has cited deletion pathologies (FluidInference/FluidAudio#128 — dropped sentences, worse on v3; mitigations in FluidAudio#177). Dictation speaks *about* speech constantly, so this axis belongs in any engine bakeoff here.
- **Cohere Transcribe is measured (round 2 addendum):** 3.41% WER / 97 ms warm / 4.1 GB RSS via mlx-audio 0.5.0 — asset 26's Core ML numbers (532 ms, ~12 GB) are superseded; the runtime question is answered. But Parakeet wins every column of the full 4×6 e2e matrix, and Cohere+s1-mini (superwhisper's own offline stack) loses to Parakeet+s1-mini on both axes (9/27 @ 172 ms vs 12/27 @ 107 ms). What Cohere uniquely buys: it hears the meta-speech Parakeet deletes — quote/unquote resolved into real quotation marks, spelled letters kept — one corpus entry today, but the exact shape of a fallback's value. Like whisper, it silently deletes disfluencies.
- **Round 3 (hosted engines):** ElevenLabs Scribe v2 is the first engine to beat Parakeet — 0.98% WER vs 1.95% — and takes every e2e cleanup column except s1-mini's (best cell: Scribe+gemini 21/27). It hears everything Parakeet deletes, and its `keyterms` conditioning hits 17/18 recall at 2 traps. The costs are categorical: ~640 ms network latency and audio leaving the machine — a different consent class than transcripts. Groq-hosted whisper-turbo ties local whisper at the same wall clock (hosting whisper buys nothing on an M4 Pro); Gemini-as-engine paraphrases what it hears — disqualifying in a transcriber. Vocabulary conditioning is now an engine-selection axis: whisper `--prompt` and Scribe `keyterms` exist, Parakeet has no channel at all.
