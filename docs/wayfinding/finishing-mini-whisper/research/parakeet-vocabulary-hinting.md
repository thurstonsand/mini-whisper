# Parakeet vocabulary hinting

## Verdict

**FluidAudio has a real custom-vocabulary facility, and MiniWhisper's pinned v0.15.5 already contains it.** It is **not** an initial prompt, TDT decoder-logit bias, or an argument on `AsrManager.transcribe`. It first decodes with Parakeet TDT, then runs a separate Core ML Parakeet CTC model over the same audio and uses CTC acoustic scores plus a fixed boost to decide whether to replace an already-decoded TDT word or phrase. This is audio-grounded CTC-WS-style _post-decode rescoring_, not a blind find/replace, but it still rewrites text after the primary TDT decode. [FluidAudio v0.15.5 CLI implementation](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudioCLI/Commands/ASR/Parakeet/SlidingWindow/TranscribeCommand.swift#L483-L564) [FluidAudio v0.15.5 scoring implementation](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/Rescorer/VocabularyRescorer%2BTokenEvaluation.swift#L44-L115)

For MiniWhisper's Parakeet TDT v2, this is the only credible local recognition-time-ish vocabulary path presently exposed. It requires an explicit CTC sidecar integration in `ASREngine`; it is **not enabled merely by persisting dictionary words**. The lower-level `AsrManager` MiniWhisper uses accepts audio, decoder state, and an optional language only, while the custom-vocabulary session API belongs to the separate `SlidingWindowAsrManager`. [MiniWhisper `ASREngine.swift:70-72`](../../../../Packages/ASREngine/Sources/ASREngine/ASREngine.swift#L70-L72) [FluidAudio v0.15.5 `AsrManager` overloads](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/TDT/AsrManager.swift#L341-L501) [FluidAudio v0.15.5 session API](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/SlidingWindowAsrManager.swift#L81-L121)

There is no need to upgrade from v0.15.5 to obtain the facility: MiniWhisper pins exactly v0.15.5 / `19600a485baa4998812e4654b70d2bab8f2c9949`, and FluidAudio's release list presently ends at v0.15.5. [MiniWhisper `Packages/ASREngine/Package.swift:8-13`](../../../../Packages/ASREngine/Package.swift#L8-L13) [MiniWhisper `Packages/ASREngine/Package.resolved:5-11`](../../../../Packages/ASREngine/Package.resolved#L5-L11) [FluidAudio releases](https://github.com/FluidInference/FluidAudio/releases)

## What FluidAudio exposes

### Availability and public shape

The public vocabulary types and `SlidingWindowAsrManager.configureVocabularyBoosting(vocabulary:ctcModels:config:)` were already present in v0.13.4, so they also exist in v0.15.5. The caller supplies a `CustomVocabularyContext`, preloaded `CtcModels`, and optionally `VocabularyRescorer.Config`; the method stores them on the manager and builds the spotter/rescorer once. [FluidAudio v0.13.4 API](https://github.com/FluidInference/FluidAudio/blob/v0.13.4/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/SlidingWindowAsrManager.swift#L76-L116) [FluidAudio v0.15.5 API](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/SlidingWindowAsrManager.swift#L58-L121)

```swift
let vocabulary = CustomVocabularyContext(terms: [
  CustomVocabularyTerm(text: "MiniWhisper", aliases: ["Mini Whisper"]),
  CustomVocabularyTerm(text: "Thurston"),
])
let ctcModels = try await CtcModels.downloadAndLoad(variant: .ctc110m)
try await slidingWindowManager.configureVocabularyBoosting(
  vocabulary: vocabulary,
  ctcModels: ctcModels
)
```

`CustomVocabularyTerm` has `text`, optional `weight`, `aliases`, optional TDT and CTC token IDs, and an optional per-term `minSimilarity`; `CustomVocabularyContext` holds the term list plus global thresholds and `minTermLength`. The convenience `loadWithCtcTokens(from:)` accepts a JSON configuration or line-based text file, downloads/loads CTC assets, and tokenizes the terms for the CTC model. [FluidAudio v0.15.5 term/context source](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/CustomVocabularyContext.swift#L3-L123) [FluidAudio v0.15.5 loading/tokenization source](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/CustomVocabularyContext.swift#L257-L315)

For a batch `AsrManager` client such as MiniWhisper, v0.15.5 exposes the lower-level pieces rather than an integrated per-call parameter: create `CtcKeywordSpotter`, call `spotKeywordsWithLogProbs(audioSamples:customVocabulary:)`, create `VocabularyRescorer`, then call `ctcTokenRescore(transcript:tokenTimings:logProbs:frameDuration:cbw:marginSeconds:minSimilarity:)`. FluidAudio's own file-mode CLI follows exactly that sequence after `AsrManager.transcribe`; its documentation's example of `asrManager.transcribe(audioSamples, customVocabulary:)` does **not** match any v0.15.5 `AsrManager` overload. [FluidAudio v0.15.5 CLI batch path](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudioCLI/Commands/ASR/Parakeet/SlidingWindow/TranscribeCommand.swift#L483-L564) [FluidAudio v0.15.5 spotter API](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/WordSpotting/CtcKeywordSpotter.swift#L99-L179) [FluidAudio v0.15.5 rescorer API](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/Rescorer/VocabularyRescorer%2BTokenRescoring.swift#L180-L234) [stale documentation example](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Documentation/ASR/CustomVocabulary.md#L540-L563) [actual `AsrManager` API](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/TDT/AsrManager.swift#L341-L501)

This makes the normal batch path **per transcription** for CTC inference/rescoring, but CTC models, tokenizer, and a vocabulary-specific rescorer can be retained across transcriptions. The integrated sliding-window path is **per manager/session**: configure before `start`, then it rescans only confirmed windows. [FluidAudio v0.15.5 streaming setup](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/SlidingWindowAsrManager.swift#L81-L121) [FluidAudio v0.15.5 confirmed-window application](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/SlidingWindowAsrManager.swift#L487-L523)

### Mechanism: CTC sidecar rescoring, not TDT conditioning

The sidecar is a separate CTC Core ML `MelSpectrogram` plus `AudioEncoder` and `vocab.json`; it produces CTC log probabilities. The spotter scores every tokenized custom term against those probabilities, then the rescorer searches around the TDT word timing, scores both the original phrase and candidate with constrained CTC dynamic programming, adds the context-biasing weight to the candidate score, and rewrites only if the boosted candidate exceeds the original. [FluidAudio v0.15.5 CTC assets and loader](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/WordSpotting/CtcModels.swift#L33-L57) [FluidAudio v0.15.5 CTC inference pipeline](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/WordSpotting/CtcKeywordSpotter%2BInference.swift#L12-L25) [FluidAudio v0.15.5 score comparison](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/Rescorer/VocabularyRescorer%2BTokenEvaluation.swift#L36-L115)

So calling it “shallow fusion” follows FluidAudio and NeMo terminology, but calling it TDT logit bias would be inaccurate: the TDT greedy decode has already committed its words, and FluidAudio substitutes text afterward based on an auxiliary model's audio evidence. It is materially stronger than a plain fuzzy post-pass because the replacement must win a CTC acoustic comparison. [FluidAudio v0.15.5 rescorer description](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/Rescorer/VocabularyRescorer.swift#L3-L12) [FluidAudio v0.15.5 CLI rewrite](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudioCLI/Commands/ASR/Parakeet/SlidingWindow/TranscribeCommand.swift#L538-L561)

Parakeet TDT v2 has no built-in CTC head, so the selected MiniWhisper artifact cannot supply these CTC scores itself; FluidAudio documents a separate CTC 110M encoder for v2/v3. The selected artifact is indeed the v2 Core ML repository at a pinned revision. [FluidAudio v0.15.5 v2/v3 compatibility and sidecar cost](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Documentation/ASR/CustomVocabulary.md#L20-L36) [FluidAudio v0.15.5 separate-encoder requirement](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Documentation/ASR/CustomVocabulary.md#L135-L161) [MiniWhisper `PinnedModelStore.swift:24-25`](../../../../Packages/ASREngine/Sources/ASREngine/PinnedModelStore.swift#L24-L25)

### Cost, limits, and accuracy risk

The sidecar means another model download/load, an extra encoder pass over every boosted utterance, and CTC dynamic-programming work for every dictionary term. FluidAudio's own v2/v3 documentation estimates a 97.5 MB additional model, roughly 130 MB peak RAM total, and 25.98x real-time throughput; treat those as upstream benchmark figures, not MiniWhisper measurements. [FluidAudio v0.15.5 resource/throughput table](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Documentation/ASR/CustomVocabulary.md#L135-L147) [FluidAudio v0.15.5 per-term spotting loop](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/WordSpotting/CtcKeywordSpotter.swift#L101-L178)

There is no hard count cap in the v0.15.5 API. Its defaults tighten `minSimilarity` from 0.50 at ≤10 terms, to 0.55 for 11–100, to 0.60 above 100 because more dictionary distractors cause false replacements; the docs call 1–50 excellent, 50–100 good, and report testing through 230 terms. Terms shorter than `minTermLength` (default 3) are skipped, and the rescorer adds stricter short-word, length-ratio, and stopword guards. [FluidAudio v0.15.5 size-aware thresholds](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/ContextBiasingConstants.swift#L178-L255) [FluidAudio v0.15.5 vocabulary guidance](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Documentation/ASR/CustomVocabulary.md#L620-L632) [FluidAudio v0.15.5 guards](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/ContextBiasingConstants.swift#L81-L140)

The quality trade-off is real, not theoretical. MacParakeet's reproducible FluidAudio 0.15.4 experiment found a 50-term synthetic OOV set improved exact recall from 22% to 84% with the default large-list threshold, but produced nine false applied terms; raising `minSimilarity` to 0.65 reduced recall to 74% and false applications to one. On full LibriSpeech test-clean, the strict condition changed WER from 2.312% to 2.414% and throughput from 103.1x to 31.4x realtime; the experiment explicitly warns that its synthetic speech is not human-dictation QA. [MacParakeet Phase 0 method caveat](https://github.com/moona3k/macparakeet/blob/main/docs/research/2026-07-04-custom-vocab-phase0.md#L122-L125) [MacParakeet Phase 0 results](https://github.com/moona3k/macparakeet/blob/main/docs/research/2026-07-04-custom-vocab-phase0.md#L228-L274)

## NVIDIA/NeMo versus the shipped Core ML path

NeMo offers several different facilities. Flashlight word boosting is CTC beam decoding with a KenLM binary plus lexicon and only works in lexicon-decoding mode. Current NeMo also documents GPU-PB, a CUDA/GPU token-level boosting tree for CTC, RNN-T/TDT, and AED decoding. Neither is an option in FluidAudio's Apple Core ML TDT v2 runtime. [NVIDIA NeMo word boosting: GPU-PB](https://docs.nvidia.com/nemo-framework/user-guide/latest/nemotoolkit/asr/asr_customization/word_boosting.html) [NVIDIA NeMo word boosting: Flashlight](https://docs.nvidia.com/nemo-framework/user-guide/latest/nemotoolkit/asr/asr_customization/word_boosting.html)

NeMo's relevant portable idea is **CTC-WS**: build a context graph from user phrases, score it against CTC log probabilities, compare/filter candidates against greedy CTC output, then merge them into a Transducer result. Crucially, NeMo says a Transducer needs a _hybrid Transducer-CTC model_ (shared encoder with CTC and Transducer heads) for that direct route. [NVIDIA NeMo CTC-WS documentation](https://docs.nvidia.com/nemo-framework/user-guide/latest/nemotoolkit/asr/asr_customization/word_boosting.html) [NVIDIA NeMo context-biasing source](https://github.com/NVIDIA-NeMo/Speech/blob/main/nemo/collections/asr/parts/context_biasing/context_biasing_utils.py)

FluidAudio has ported that CTC-WS pattern to Core ML, but it does so with a separately shipped CTC Core ML model for v2/v3, not by retaining NeMo's Python decoder, Flashlight, KenLM, GPU-PB, or a CTC head in MiniWhisper's pure-TDT v2 bundle. Therefore: **CTC-WS-style rescoring survives only if MiniWhisper downloads and runs FluidAudio's CTC sidecar; NeMo's actual decode-time facilities do not survive the selected conversion.** [FluidAudio v0.15.5 CTC-WS implementation note](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/WordSpotting/CtcDPAlgorithm.swift#L1-L9) [FluidAudio v0.15.5 v2/v3 architecture](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Documentation/ASR/CustomVocabulary.md#L27-L36) [FluidAudio v0.15.5 CTC asset requirement](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/WordSpotting/CtcModels.swift#L62-L75)

## What other dictation apps actually do

- **MacParakeet is the directly relevant precedent.** It uses FluidAudio's CTC models, tokenizer, spotter, and `VocabularyRescorer` after Parakeet TDT completion; it caches models and vocabulary-specific rescorers, and passes the original audio and TDT token timings to the sidecar. It also keeps a separate deterministic whole-word replacement pipeline. Its runtime preference currently defaults recognition boosting to off, while its ordinary clean corrections continue; that is a useful signal about the remaining product risk. [MacParakeet FluidAudio integration](https://github.com/moona3k/macparakeet/blob/main/Sources/MacParakeetCore/STT/CustomVocabularyBoosting.swift#L244-L340) [MacParakeet caching and construction](https://github.com/moona3k/macparakeet/blob/main/Sources/MacParakeetCore/STT/CustomVocabularyBoosting.swift#L342-L505) [MacParakeet default-off preference](https://github.com/moona3k/macparakeet/blob/main/Sources/MacParakeetCore/AppRuntimePreferences.swift#L681-L683) [MacParakeet replacement mechanism](https://github.com/moona3k/macparakeet/blob/main/Sources/MacParakeetCore/TextProcessing/CustomWordReplacer.swift#L12-L63)
- **Hex does not use FluidAudio vocabulary biasing.** Its Parakeet client calls ordinary `AsrManager.transcribe`, and its “word remapping” feature is a case-insensitive, whole-word regular-expression substitution after transcription. [Hex Parakeet client](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/ParakeetClient.swift#L123-L131) [Hex remapping implementation](https://github.com/kitlangton/Hex/blob/main/HexCore/Sources/HexCore/Models/WordRemapping.swift#L22-L40)
- **VoiceInk separates three things:** Whisper receives a prompt, FluidAudio/Parakeet is called without one, and its vocabulary is sent as instructions only to optional AI enhancement. Its deterministic replacement service then applies case-insensitive exact matches; there is no FluidAudio vocabulary-sidecar or fuzzy phonetic dictionary path in the Parakeet client. [VoiceInk request context, where prompt is Whisper-only](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Transcription/Engine/TranscriptionService.swift#L5-L17) [VoiceInk FluidAudio transcription](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Transcription/FluidAudio/FluidAudioTranscriptionService.swift#L178-L197) [VoiceInk enhancement vocabulary injection](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Services/AIEnhancement/AIEnhancementService.swift#L153-L184) [VoiceInk exact replacement implementation](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Transcription/Processing/WordReplacementService.swift#L9-L67)

## Upgrade path and recommendation for the dictionary ticket

1. **Do not upgrade FluidAudio just for vocabulary support.** v0.15.5 already has every API needed for a v2 CTC-sidecar experiment. Main has added an untagged `ctcTokenEvaluateCandidates(...)` API that returns evidence without rewriting the transcript, but no newer release exists; adopting it would mean tracking unreleased upstream and still does not create TDT decode-time bias. [FluidAudio v0.15.5 release status](https://github.com/FluidInference/FluidAudio/releases) [post-v0.15.5 candidate-evidence commit](https://github.com/FluidInference/FluidAudio/commit/46785b0c9c8f869be4cfd3c3ee65cf4aa3290954) [current API](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/Rescorer/VocabularyRescorer%2BTokenRescoring.swift#L361-L403)
2. **If the product wants genuine acoustic evidence, plan a bounded v0.15.5 CTC-sidecar spike before building dictionary UI.** Keep the selected TDT v2 and its established merger; download/validate the CTC 110M assets separately, cache them and a tokenized vocabulary by dictionary revision, serialize the extra Core ML work with the engine, and benchmark real MiniWhisper dictations for stop latency, term recall, and false substitutions. This is the MacParakeet pattern, and its quality data shows a stricter threshold is mandatory rather than cosmetic. [MiniWhisper engine selection and current direct call](../../../../Packages/ASREngine/Sources/ASREngine/ASREngine.swift#L70-L72) [MacParakeet strict-gate evidence](https://github.com/moona3k/macparakeet/blob/main/docs/research/2026-07-04-custom-vocab-phase0.md#L249-L274)
3. **Do not describe it as a prompt or as guaranteed correction.** It can improve rare names and jargon, but it sometimes replaces correctly recognized words with dictionary entries. The UI should either disclose that this is an experimental recognition boost or wait until the corpus gate proves the selected thresholds safe. [FluidAudio safeguards](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Documentation/ASR/CustomVocabulary.md#L369-L390) [MacParakeet false-replacement evidence](https://github.com/moona3k/macparakeet/blob/main/docs/research/2026-07-04-custom-vocab-phase0.md#L263-L274)
4. **If the sidecar is rejected for latency, memory, or false positives, there is no alternate TDT-v2 model-level biasing API to fall back to.** The remaining fallback is post-ASR correction: exact user-authored replacements are what Hex and VoiceInk ship; a fuzzy/phonetic matcher could use FluidAudio's optional BK-tree/Levenshtein candidate generation, but it has no acoustic proof and should be treated as a separate, higher-risk feature rather than disguised as vocabulary hinting. [FluidAudio BK-tree and edit-distance mechanism](https://github.com/FluidInference/FluidAudio/blob/v0.15.5/Documentation/ASR/CustomVocabulary.md#L588-L618) [Hex exact remapping](https://github.com/kitlangton/Hex/blob/main/HexCore/Sources/HexCore/Models/WordRemapping.swift#L22-L40) [VoiceInk exact replacement](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Transcription/Processing/WordReplacementService.swift#L9-L67)

The ticket's existing scope explicitly excludes word remapping. On that scope, the honest decision is binary: ship the CTC-sidecar experiment after it passes MiniWhisper's regression corpus, or defer the dictionary surface; a stored word list alone cannot influence Parakeet TDT v2.
